# Token Monitor 0.93.1

<!-- app-update-notes:en:start -->
### Fixed
- Probe active Windows named pipes (`\\\\.\\pipe\\token-monitor-approval-*`) before binding the local approval alert bridge so a second process cleanly receives `already_owned` instead of opening a competing listener.
- Clean up idle probe timers on socket close and give subprocess hook dispatch timing assertions headroom on loaded Windows runners while still asserting non-blocking return before alert delivery finishes.
### Notes
- Carries forward all 0.93.0 read-only Codex (`PermissionRequest`) and Antigravity (`PreToolUse`) approval alert features; alerts remain disabled by default across Hub, collector, and Android, and confirmations always stay on the desktop.
<!-- app-update-notes:en:end -->

<!-- app-update-notes:zh:start -->
### 修复
- 启动本地审批提醒 IPC 桥时，在 Windows 命名管道（`\\\\.\\pipe\\token-monitor-approval-*`）也先执行存活探测，避免第二个进程重复监听并确保返回 `already_owned`。
- 在连接关闭时及时清理读取超时定时器，并在钩子子进程测试中为高负载 Windows CI 保留足够的进程拉起余量，同时严格验证早于异步送达的非阻塞返回。
### 说明
- 包含 0.93.0 全部只读 Codex（`PermissionRequest`）与 Antigravity（`PreToolUse`）审批提醒能力；开关在 Hub、采集端与 Android 默认全部关闭，允许与拒绝操作始终保留在电脑端。
