# 会话实时速率

在桌面会话详情或 Android 的“性能与上下文”中打开 Antigravity / Codex 会话，即开始观察所选来源设备的输出速率。多设备副本独立计算，可在卡片内切换来源；离线时不会自动换到另一个副本。进入页面前的五分钟不会被补算。

## 读数口径

速率使用设备统计快照中该会话的真实 `outputTokens` 计数和来源 `updatedAt`：

```text
tok/s   = (本次 outputTokens − 上次 outputTokens) × 1000 / 来源时间差（毫秒）
tok/min = tok/s × 60
```

两个数表示同一个观测间隔，分钟值不是最近一分钟的滑动平均。输入、缓存、推理或会话累计匹配计时不参与；Android 原有“历史匹配均速（非实时）”单独保留，不能作为实时读数的替代。

这是**来源计数的实时变化率**。精度取决于来源日志更新与采集频率：若工具只在回复结束时写入用量，一次新增会形成批量观测，不能解释为回复过程中的逐 Token 流速。应用不代理模型请求，也不会从正文长度估算 Token。需要逐 Token 流速时，必须另外取得来源的流式 Token 计数。

## 等待、失效与趋势

- 两次有效且时间递增的来源快照才能产生首个读数。重复推送、网页重绘和 Hub 读取时间不产生新样本。
- 新快照明确没有新增输出时可以显示零；缺失计数、来源离线或 Hub 不可用时显示“—”。
- 当前速率在来源时间超过 15 秒后失效；来源快照超过 30 秒或相邻观测间隔超过 30 秒时重新建立基线，不把断线期间的输出平均到当前速率。
- 计数回退、同一时间戳的计数修正、周期切换或来源切换会重新开始。迟到的旧快照不能覆盖较新的观测。
- 曲线使用固定五分钟时间轴和实际观测间隔的阶梯线。断线留下空档，不插值、不平滑、不补造零。最多在内存保留 360 个间隔；后台暂停采样，离开详情后释放监控。

统计沿用现有 Hub / SSE 通道，不增加轮询、日志扫描或正文采集，也不在 Hub、历史数据库、微件或通知中存储这条曲线。旧 Hub 只要提供有效的设备时间戳与输出计数即可使用；缺少数据时保持不可用。

## CC Switch 参考

调查基于 [CC Switch `3a0b86a`](https://github.com/farion1231/cc-switch/tree/3a0b86a26649f61d86dfbc3878d73220199f70b2)：其 [SSE 响应处理](https://github.com/farion1231/cc-switch/blob/3a0b86a26649f61d86dfbc3878d73220199f70b2/src-tauri/src/proxy/response_processor.rs#L399)记录首个输出事件时间，[Codex 会话用量读取](https://github.com/farion1231/cc-switch/blob/3a0b86a26649f61d86dfbc3878d73220199f70b2/src-tauri/src/services/session_usage_codex.rs)另有从日志推导的请求计时。请求完成后的计时与实时计数变化是不同读数；本功能采用独立的增量观测实现，没有复制代理请求平均速度或引入代理依赖。
